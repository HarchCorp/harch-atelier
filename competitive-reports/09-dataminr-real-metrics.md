### 5.2 SLA — Service Availability (verified)

Source: https://www.dataminr.com/legal/sla (Dataminr official SLA legal page)

- **Service availability SLA**: **99% monthly** ✅
- Calculation: `Availability = (Total minutes in month - Downtime) / Total minutes in month`
- **Downtime definition**: Key Services interrupted for **>5 consecutive minutes** for the majority of Customer's Authorized Users
- **Support response for Downtime**: 1 hour (24/7)
- **Other support response**: 2–24 hours (24/5 basis)
- **SLA breach trigger**: Services fail to meet 99% during 2 consecutive calendar months OR 3 times in 6 consecutive calendar months
- **Scheduled maintenance**: excluded from Downtime; 48 hours advance notice required via in-app messaging or direct communication from Customer's account manager
- **Compensation**: Service credits (specific formula not in extract)

**Critical observation**: A 99% monthly uptime SLA = ~7.2 hours of allowed downtime per month = ~87 hours per year. This is **significantly weaker** than typical enterprise SaaS SLAs (99.9% = 43 min/month, 99.99% = 4.3 min/month). For a "real-time alerting" platform, this is a notably loose commitment.

### 5.3 Inference / Generation Latency (verified, qualitative)

## 6. EXACT THROUGHPUT

### 6.1 Ingestion Throughput (verified)

- **Daily volume**: 43 TB / day ✅ (= ~500 MB/sec average; likely peaks much higher)
- **Raw signals ingested**: Billions per day ✅
- **Labels added (enrichment)**: **Millions per second** ✅ (Aerospike case study)
- **Daily computations**: **Trillions per day** ✅ (Dataminr LLM blog)

### 6.2 Throughput Math (🔧 derived)

- 43 TB/day ÷ 86,400 sec/day = **~500 MB/sec average ingest** (peaks likely 5-10x during major events)
- Billions of signals/day ÷ 86,400 sec/day = **~10,000–50,000 signals/sec average** (depending on "billions" — 1B = ~11.6K/sec, 5B = ~58K/sec)
- Trillions of computations/day ÷ 86,400 sec/day = **~10M–50M computations/sec average** (depending on "trillions" — 1T = ~11.6M/sec, 5T = ~58M/sec)

### 6.3 Pipeline Architecture (verified — Aerospike case study)

1. **Ingestion layer**: Public data sources (1M+) streamed via cloud-native pipeline into Dataminr's enrichment cluster
2. **AI enrichment pipeline**: **50+ AI models** in tandem, each requiring rapid reads/writes as they add metadata and pass updated signals forward
3. **Real-time datastore**: **Aerospike on AWS** (replaced DynamoDB + Redis two-database pattern)
4. **Raw content reduction**: >95% reduction before alert generation
5. **Predictive AI**: Classifies, enriches, correlates signals using 50+ proprietary LLMs + Foundation Models
6. **Generative AI (ReGenAI)**: Creates live, dynamically updating event briefs
7. **Knowledge Graph**: Millions of entities for contextualization + hallucination mitigation
8. **Vector database**: Integrated for semantic discovery (vendor not disclosed)
9. **Output**: Alerts (mobile push, email, API, webhook), briefs (ReGenAI), dashboard updates

### 6.4 Pre-Aerospike Bottleneck (verified)

The Aerospike case study documents the pre-migration bottleneck:
- "Dataminr reached the limits of its Redis-based in-memory system as data volume and model complexity surged"
- "The existing data layer struggled to support this high rate of small, sequential operations"
- "in-memory constraints prevented Dataminr from scaling to larger message payloads, richer metadata, and higher throughput"
- Solution: Aerospike consolidation eliminated two-database (DynamoDB + Redis) operational overhead

## 9. DETECTION ARCHITECTURE

### 9.1 Multi-Modal Fusion AI Pipeline (verified)

Per Dataminr Multi-Modal Fusion AI blog (Feb 18, 2020):

1. **Input**: Image-text pairs from public data sources (social posts, news, sensor data)
2. **Image feature extraction**: Computer Vision model generates feature map for the image
3. **Text embedding**: NLP model generates word embeddings for the text
4. **Cross-modal attention**: Deep Learning attention mechanism fuses information from both modalities, weighting important patches/words
5. **Event classification**: Fused representation classified into event types (wildfire, cyber-physical attack, protest, etc.)
6. **Cross-corroboration**: Cross-references with sensor data, Knowledge Graph entities, and historical archive
7. **Output**: Real-time alert with severity, location, confidence score, source attribution

### 9.2 Predictive AI vs. Generative AI Split (verified)

- **Predictive AI**: Detects events from public data patterns; classifies event type, location, severity, interconnections. Backbone of Multi-Modal Fusion AI + Human-AI Feedback loops.
- **Generative AI**: Creates textual descriptions + real-time summaries (ReGenAI briefs). **95% of alert summaries are AI-generated** (Oct 2023); described as "indistinguishable from summaries written by humans"
- **Vector databases**: Integrated for semantic discovery (vendor not disclosed)
- **Knowledge Graph**: Mitigates LLM hallucinations by grounding outputs in fixed domain-specific referential points

### 9.3 Pipeline (verified)

1. **Ingestion**: 43 TB/day from 1M+ public sources across text/image/video/audio/sensor in 150+ languages
2. **AI enrichment**: 50+ proprietary models add metadata + labels (millions/sec)
3. **Raw content reduction**: >95% filtering before alert generation
4. **Predictive AI**: Event classification, location, severity, interconnection
5. **Cross-modal fusion**: Multi-modal attention mechanism across text/image/video/audio
6. **Knowledge Graph integration**: Entity resolution + relationship mapping
7. **Generative AI (ReGenAI)**: Dynamic event brief generation with 99.5% accuracy
8. **Output**: Push alerts (mobile, email, API, webhook, Splunk, ServiceNow, Slack, Teams), dashboard updates, ReGenAI briefs
