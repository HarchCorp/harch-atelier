Work Log:

- Read `src/lib/mock-data.ts` to mirror the `WatchlistSignal` / `Severity` / `RiskPillar` shapes exactly (8 baseline signals, WL-001 through WL-008). The mini-service keeps a local copy of these types so it stays self-contained and does not import from the Next.js app.
- Created `/home/z/my-project/mini-services/signal-pulse/` as an independent bun project:
  - `package.json` — name `signal-pulse`, private, ESM (`"type": "module"`). `dev` script uses `bun --hot index.ts` for auto-restart on file change. Deps: `socket.io@^4.7.5`. Dev deps: `@types/node`, `typescript` (for optional `bun run typecheck`). No other deps — kept minimal.
  - `tsconfig.json` — strict TS, ES2022 / Bundler module resolution, `noEmit`.
  - `index.ts` — the full server (see below).
- Server behaviour (`index.ts`):
  - `httpServer` + `socket.io` Server, **port 3003 hardcoded** (no env), `path: "/"`, `cors: { origin: "*", methods: ["GET","POST"] }`, `pingTimeout: 60000`, `pingInterval: 25000`.
  - In-memory `signals[]` array seeded with the 8 baseline signals; `updatedAt` rewritten to `new Date().toISOString()` on boot so the UI gets a live timestamp instead of "12m ago".
  - In-memory `kpis` state seeded from `headlineKpis` (`riskIndex: 72.4`, `negativeShare: 38`, `activeAlerts: 17`).
  - On `connection`: logs the socket id, immediately emits `signals:snapshot` (the full 8-signal array) and `kpis:tick` (current kpi state) so the client hydrates instantly.
  - `scheduleNextUpdate()`: every 4–7s (randomised per-tick via `randInt(4000,7000)`), picks a random signal id, mutates `delta` by ±0.1–±1.5 (rounded to 2 decimals, clamped to ±10), bumps `articles` by +1–+8, refreshes `updatedAt` to now, and with a 10% chance flips `severity` one level up or down (within `low → medium → high → critical`). Emits `signal:update` with the single patched signal. Uses `setTimeout` recursion so the cadence is genuinely random rather than a fixed interval.
  - `scheduleNextKpiTick()`: every 30s (via `setInterval`), drifts `riskIndex` ±0.4, `negativeShare` ±0.6pp, and `activeAlerts` by −1/0/+1 (weighted), then emits `kpis:tick` with the new values + a fresh `ts` ISO string.
  - Graceful shutdown on SIGTERM / SIGINT — closes io then httpServer.
- Installed deps: `cd mini-services/signal-pulse && bun install` → 23 packages (socket.io@4.8.3, @types/node@22.20.1, typescript@5.9.3). Started in background: `bun run dev > service.log 2>&1 &`. Confirmed listening on port 3003 via `lsof -i :3003` (PID 3475, IPv6 *:3003 LISTEN).
- Smoke-tested the service end-to-end with a temporary `socket.io-client` script (`/tmp/smoke-test.ts`, since deleted from the test path — not part of the repo): connected, received `signals:snapshot` (8 items) on connect, received `kpis:tick` (drifted values), received `signal:update` (WL-007 patched). All three event names fire, all payloads match the spec'd shape.
- Installed `socket.io-client@4.8.3` into the MAIN project (`bun add socket.io-client` in `/home/z/my-project`) — it was not previously in `package.json` / `node_modules`.
- Created `/home/z/my-project/src/hooks/use-signal-pulse.ts` — the ONLY file touched under `src/`. Details:
  - `"use client"` module.
  - Exports `useSignalPulse()` hook + types `WatchlistSignal` (re-exported from `@/lib/mock-data`) and `PulseKpis` (defined locally).
  - Connects to `io("/?XTransformPort=3003", { transports: ["websocket","polling"], reconnection: true, reconnectionAttempts: Infinity, reconnectionDelay: 1000, reconnectionDelayMax: 10000, timeout: 10000 })`. NEVER a direct localhost:3003 URL.
  - SSR-safe: socket is only created inside `useEffect`, so the first server-rendered paint uses the static `watchlistSignals` baseline and matches the client's first render (no hydration mismatch).
  - Initial `signals` state seeded from `watchlistSignals` (imported from `@/lib/mock-data`) — so the table renders immediately even before the socket connects.
  - On `signals:snapshot`: replaces the whole array (server snapshot is authoritative).
  - On `signal:update`: patches the matching signal by `id` via `prev.map(...)`.
  - On `kpis:tick`: replaces the kpis state.
  - On `connect` / `disconnect`: flips the `connected` boolean.
  - Cleanup: removes all listeners, calls `socket.disconnect()`, sets `connected` to false. socket.io handles reconnection automatically.
  - Returns `{ signals: WatchlistSignal[], kpis: PulseKpis | null, connected: boolean }`.
- `bun run lint` (in the main project): 0 errors. The new hook passes ESLint + Next.js rules cleanly.
- Did NOT modify `src/app/page.tsx`, `src/components/**`, `src/lib/mock-data.ts`, or any other existing dashboard file. The orchestrator/main agent is free to wire `useSignalPulse()` into the WatchlistSignals table and KPI strip when ready.
