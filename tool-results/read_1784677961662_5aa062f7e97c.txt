    65→- Created `/home/z/my-project/mini-services/signal-pulse/` as an independent bun project:
    66→  - `package.json` — name `signal-pulse`, private, ESM (`"type": "module"`). `dev` script uses `bun --hot index.ts` for auto-restart on file change. Deps: `socket.io@^4.7.5`. Dev deps: `@types/node`, `typescript` (for optional `bun run typecheck`). No other deps — kept minimal.
    67→  - `tsconfig.json` — strict TS, ES2022 / Bundler module resolution, `noEmit`.
    68→  - `index.ts` — the full server (see below).
    69→- Server behaviour (`index.ts`):
    70→  - `httpServer` + `socket.io` Server, **port 3003 hardcoded** (no env), `path: "/"`, `cors: { origin: "*", methods: ["GET","POST"] }`, `pingTimeout: 60000`, `pingInterval: 25000`.
    71→  - In-memory `signals[]` array seeded with the 8 baseline signals; `updatedAt` rewritten to `new Date().toISOString()` on boot so the UI gets a live timestamp instead of "12m ago".
    72→  - In-memory `kpis` state seeded from `headlineKpis` (`riskIndex: 72.4`, `negativeShare: 38`, `activeAlerts: 17`).
    73→  - On `connection`: logs the socket id, immediately emits `signals:snapshot` (the full 8-signal array) and `kpis:tick` (current kpi state) so the client hydrates instantly.
    74→  - `scheduleNextUpdate()`: every 4–7s (randomised per-tick via `randInt(4000,7000)`), picks a random signal id, mutates `delta` by ±0.1–±1.5 (rounded to 2 decimals, clamped to ±10), bumps `articles` by +1–+8, refreshes `updatedAt` to now, and with a 10% chance flips `severity` one level up or down (within `low → medium → high → critical`). Emits `signal:update` with the single patched signal. Uses `setTimeout` recursion so the cadence is genuinely random rather than a fixed interval.
    75→  - `scheduleNextKpiTick()`: every 30s (via `setInterval`), drifts `riskIndex` ±0.4, `negativeShare` ±0.6pp, and `activeAlerts` by −1/0/+1 (weighted), then emits `kpis:tick` with the new values + a fresh `ts` ISO string.
    76→  - Graceful shutdown on SIGTERM / SIGINT — closes io then httpServer.
    77→- Installed deps: `cd mini-services/signal-pulse && bun install` → 23 packages (socket.io@4.8.3, @types/node@22.20.1, typescript@5.9.3). Started in background: `bun run dev > service.log 2>&1 &`. Confirmed listening on port 3003 via `lsof -i :3003` (PID 3475, IPv6 *:3003 LISTEN).

    90→  - Cleanup: removes all listeners, calls `socket.disconnect()`, sets `connected` to false. socket.io handles reconnection automatically.

   824→## Phase 1 — Reasoning about what a HarchCorp trader actually needs
   825→
   826→A HarchCorp trader sits at a multi-screen desk and their minute-by-minute concerns are very different from a risk analyst or comms officer. They care about (in priority order):
   827→
   828→1. **The Casablanca board at a glance** — MASI index intraday ticks (is the market up or down today?), 30-day trend (are we in a rally or pullback?), session breadth (advancers vs decliners), and turnover (is there liquidity?). Without this they can't even start their day.
   829→2. **Casablanca-listed equities** — real tickers (ATW, IAM, BOA, CIH, LBV, OLC, MNG, LHM, OCP, ADH, RIS, etc.) with last price, %chg, volume, market cap, P/E. They need a sortable screener they can filter by sector. Clicking a row should reveal a 30-day sparkline + key stats so they can decide whether to add to the book.
   830→3. **Their own book** — HarchCorp's open positions with mark-to-market P&L, exposure by sector, long/short split, win rate. The blotter is the single source of truth for "are we making or losing money today?". Critical: M2M P&L must be directional (long = (last-avg)*qty, short = (avg-last)*qty).
   831→4. **Sector context** — which sector is leading/lagging the MASI? A trader needs to know if banking is the engine today or if materials are pulling the index down. Sector heatmap + comparison chart normalised to 100.
   832→5. **FX & rates** — MAD crosses (EUR/MAD, USD/MAD, GBP/MAD) because HarchCorp has FX exposure; Bank Al-Maghrib key rate because it sets the cost of capital; MAD strength index for export-competitiveness read.
   833→6. **Commodities exposure** — phosphate (OCP is a top Moroccan listing), Brent (energy import), gold (safe-haven hedge), wheat (food import), nat gas, silver. With HarchCorp notional exposure column to bridge "what's the position impact".
   834→7. **Fixed income** — BAM T-bill yield curve (13W→15Y), 2s10s spread (curve steepness), and a corporate bonds table for the credit book.
   835→
   836→Plus — and this is the intelligence bridge — they need the existing risk widgets (Risk Matrix, Media Coverage, Sentiment, Share of Voice, Risk Events, Watchlist, Activity Feed) to be navigable because risk events impact positions. A trader who reads "Ransomware affiliate claims exfiltration" needs to see immediately whether their tech-bank position is exposed.
   837→
   838→The user's "beaucoup beaucoup de graphique" mandate means every section needs at least 3–5 chart panels: line, area, bar, heatmap, scatter. No section is just a table.

  1016→What the legal counsel owns, in priority order:
  1017→
  1018→1. **Regulatory register & filing calendar** — Morocco-specific statutory deadlines (AMMC quarterly disclosures + insider-dealing declarations + Loi 17-23 ESG chapter; Bank Al-Maghrib prudential reporting; BCBS Basel III LCR/NSFR; AMO/CNSS social filings; CNPDP Loi 09-08 data-protection register + 72h breach notification; OFAC/EU/UN sanctions screening; WCO customs).
